Từ root repo, trong môi trường Python đã cài dependencies:

## API

Prefix `/api/v1`; mọi route sau yêu cầu `Authorization: Bearer <token>`.

| Method | URL | Phản hồi |
|---|---|---|
| GET | `/me/vocabulary?q=&sourceDocumentId=&from=&to=&skip=0&limit=20` | `items`, `total`, `skip`, `limit`; limit tối đa 100 |
| GET | `/me/vocabulary/sources` | Danh sách nguồn của user hiện tại để lọc toàn bộ thư viện |
| POST | `/me/vocabulary` | 201 mới; 200 nếu đã có cùng mục |
| DELETE | `/me/vocabulary/{entry_id}` | 204; 404 nếu không tồn tại hoặc thuộc user khác |
| DELETE | `/me/vocabulary` | 204, chỉ xóa mục của user đang đăng nhập |

Ví dụ body POST:

```json
{
  "term": "sinh học",
  "meaning": "Môn học về sự sống",
  "contextText": "Em học sinh học.",
  "sourceDocumentId": "client-document-id",
  "sourceTitle": "Bài đọc",
  "sourceKind": "paste",
  "segmentId": "paragraph-0",
  "start": 7,
  "end": 15
}
```

`meaning`/`example` và metadata nguồn có thể null. `segmentId`, `start`, `end` phải cùng có hoặc cùng thiếu; range `[start,end)` là UTF-16 trong `contextText`, phải đúng term (kể cả emoji/từ lặp). Giới hạn term 120, context 4.000 UTF-16 units, nghĩa/ví dụ 2.000 ký tự. Owner, ngày lưu và dedupe key do server tạo; request tự thêm `userId` bị từ chối. Date filter nhận ISO timestamp có timezone, khoảng `[from,to)`; giao diện đổi “đến hết ngày” thành đầu ngày hôm sau theo timezone người dùng.

Model/schema/repository/service/router đều ở các thư mục tương ứng trong `app/`; migration mới `e7b03a9c6412` nối sau `c4f1a7d92b10`. Unique constraint `(user_id, dedupe_key)` chống tạo trùng khi hai request đến đồng thời. Xóa user sẽ cascade xóa vocabulary.

## Thay đổi quyền tài khoản liên quan

Các route cũ `/users` từng đọc/sửa/xóa được tài khoản không cần auth. Để bảo vệ thư viện riêng:

- GET `/users` chỉ trả user hiện tại (không có vai trò admin trong repo).
- GET/PATCH/DELETE `/users/{id}` yêu cầu JWT chính chủ; truy cập user khác trả 404.
- POST `/users` giữ khả năng đăng ký để tương thích; frontend/test dùng `/auth/register`.
- Test display settings đã được cập nhật để xóa user bằng token chính chủ.

Nếu có client ngoài frontend đang dùng CRUD user không xác thực, cần cập nhật client đó theo quy tắc trên.

## Kiểm thử

```bash
# Root repo, dùng PostgreSQL test riêng có hậu tố _test:
python -m pytest

# Frontend:
cd frontend
npm run build
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
```

`tests/conftest.py` tự tạo database test, cần tài khoản PostgreSQL có quyền tạo DB; chỉ định `TEST_DATABASE_URL` khi muốn chọn database test khác. Không trỏ test vào dữ liệu thật.

Test backend kiểm tra JWT, A/B isolation, unique race, lọc/ngày/phân trang, source list, Unicode, validation, cascade và khóa đường vòng qua CRUD user. Frontend có test localStorage/quota, selection với emoji/từ lặp, auth lifecycle/request cũ, lưu/xóa qua component và StrictMode. Playwright có kịch bản khách ở viewport 1366px và 390px.

**Kết quả trong môi trường triển khai:** 66 test backend PostgreSQL đã pass; đã thử migration upgrade, `alembic check`, downgrade và re-upgrade trên database thử nghiệm riêng. Frontend: build và lint pass, 14 test Vitest pass. Playwright đã được thêm nhưng chưa xác nhận pass vì môi trường thực thi chặn Unix socket khi Chromium khởi động. Cần chạy `npm run test:e2e` trên máy phát triển để kiểm tra trình duyệt thật, thao tác cảm ứng và bố cục.
